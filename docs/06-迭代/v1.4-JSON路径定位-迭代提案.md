## 零、先说结论

三句话：

1. **这是补「读」的能力，不是编辑器军备竞赛。** 转换做完了，人还得把结果里的某个字段抄到代码里 ——
   中间那一步「这个字段在哪一层」现在全靠眼睛数缩进。路径定位消掉的正是这一步。
2. **内核零新增解析路径。** IR + Span 现成可用，新增的只有一个纯函数：`locate(ir, offset) → 路径段数组`。
3. **真正的风险不在算法，在交互口径。** 点在哪算「选中了元素」、点空白怎么办、键和值是否同一路径、
   320px 下多一行会不会把按钮挤掉 —— 这些口径定不清，做出来就是「点了有时有反应有时没有」，
   和本项目历史上的坑 14 / 15 同一类失败（测试全绿、真机难用）。

**建议的版本定位**：v1.4.0 是「**只加一个能力、不加一个新 tab**」的小版本。
不引入任何新权限、不碰承载形态、不动转换内核的规则，唯一动 `src/core/` 的地方是新增一个只读纯函数模块。

## 一、现状实测（代码级）

| 判断 | 依据 | 结论 |
|---|---|---|
| IR 带位置 | `src/core/ir.ts`：`JVal` 每个变体都有 `span: Span{start,end,line,col}` | ✅ 可直接做偏移 → 节点定位 |
| Span 覆盖完整字面量 | `engine.ts:316` `spanFrom(open, c.peek(-1))` —— 从 `{` 到 `}`；字符串 token 的 `raw` 含引号 | ✅ 点引号、点括号都有确定归属 |
| 偏移是**源文本**偏移 | `spanFrom` 直接取 `Token.start/end`，lexer 对原文扫描（BOM 跳过但不改写文本） | ✅ 与 CM6 的 `doc` 偏移同一坐标系（json / python / map） |
| Java 转义不可映射 | `parse/javaEsc.ts`：先 `unescapeJavaText()` 再 `lex(inner)` → Span 落在**解码后**文本 | ❌ 与源码偏移不一致，本版**不支持**（见 FR-P8） |
| 路径工具已存在但口径不同 | `ir.ts::makePath` 产出 `/a/0/b`（指针式），供类型覆盖使用 | ⚠️ 复用其转义思路，**不复用其输出格式**（用户已选 JSONPath） |
| 输出区可直接复用 | 格式化 tab 输出 = 同语言规范化结果（json/python/java 三种） | ⚠️ json/python 可二次解析定位；java 不支持 |

### 1.1 四种来源格式的可行性矩阵（决定规格边界）

| 格式化 tab 的来源 | 输入区能否定位 | 输出区能否定位 | 说明 |
|---|---|---|---|
| 标准 JSON | ✅ | ✅ | 主路径，Span 精确对齐 |
| Python 字面量 | ✅ | ✅ | 同上；`True/None`、单引号、tuple 均已由 parser 处理 |
| `Map.toString()` | ✅ | ✅ | parser 扫原文取偏移，Span 对齐 |
| Java 转义字符串 | ❌ | ❌ | 坐标系是解码后文本，**不做近似**（近似 = 给出错路径，比不给更糟） |

> **为什么不做近似**：Java 转义串里 `{\"a\":\"b\"}` 的长度与解码后 `{"a":"b"}` 不同，
> 一旦按比例估算，用户点第 5 个字符可能在另一个 key 上。**错路径比没有路径危险** ——
> 用户会照着错的路径去改代码。本项目的立场一贯是「宁可明说做不到」（参见 PRD FR-S5 的处置方式）。

## 二、用户场景（为什么值得做）

| # | 场景 | 现在怎么做 | 做完之后 |
|---|---|---|---|
| S1 | 拿到一段接口返回的 JSON，要把 `data.list[3].userName` 取到 Java/Python 代码里 | 眼睛数缩进层级，手写 `data.list[3].userName` | 点一下 `userName`，路径条已是 `$.data.list[3].userName`，点复制 |
| S2 | 联调报错说「第 3 个元素的 amount 类型不对」 | 靠肉眼在压缩 JSON 里找第 3 个元素 | 格式化后点中那个 `amount`，得到确定路径，直接回给后端 |
| S3 | 写 jsonpath / jq 过滤表达式，忘了数组下标从谁开始、某个 key 是不是带点号 | 试错 | 点目标字段拿到规范写法（含 `['a.b']` 这类退化的正确形式） |

> S3 是这次的真实增量：**路径的规范化写法本身就是一个易错点**（键名带 `.`、带空格、带中文、
> 带单引号时该怎么引用）。人写十次错三次，工具不会。

## 三、功能梳理

### 3.1 可定位元素与路径口径

| 概念 | 定义 |
|---|---|
| **可定位元素** | IR 中的每个对象成员（key 与其值视为**同一元素**）、每个数组元素、以及根节点 |
| **路径** | 从根 `$` 到该元素的 JSONPath 串，如 `$.data.list[3].userName` |
| **点 key 与点 value** | 得到**同一条路径**；差别用路径条右侧的**类型徽标**表达（键 / 字符串 / 数字 / 布尔 / null / 数组 / 对象） |

> **为什么键和值同路径**：用户点 key 的意图几乎总是「我要这个字段」。
> 若点 key 给出父容器路径，反而要再点一次值才能拿到想要的东西 —— 多一次操作、多一次困惑。
> 而「我正在看的是键还是值」这个信息不能丢，所以用徽标补，不用路径长度补。

### 3.2 触发源与落点判定

**触发源**（任一发生都重算，以**光标位置**为准，不看选区）：

| 触发 | 说明 |
|---|---|
| 单击 | `mousedown` + `selectionSet` 双挂 —— **CM6 点击同一位置不触发 `selectionSet`**，只挂一个会漏掉「再点一次」 |
| 双击 | 选中词 → 触发 `selectionSet`，已覆盖；不需额外处理 |
| 拖选 | 以选区 **head** 为准（拖到哪算哪），不显示区间 |
| 键盘 | 方向键 / Home / End 移动光标同样更新 —— 「光标在哪就是哪」比「只有鼠标算」更可预期 |

**落点判定**（按偏移递归下降，命中最深节点）：

| 落点 | 行为 |
|---|---|
| 元素字面量内部（含字符串的引号、数字、`true/False`、`null`） | 更新为该元素路径 |
| 容器的 `{` `}` `[` `]` 上 | 更新为该**容器自身**路径（最外层即 `$`） |
| `,` `:` 或空白 / 换行 / 缩进上 | **保持上一次**，不清空（否则拖动选字时路径条会闪断） |
| 文档为空、或光标在末尾之外 | 保持上一次；从未有过则显示占位「点选 JSON 中的键或值」 |
| 落在日志前缀等「不在 IR 内」的文本上 | 保持上一次 |

> 「保持上一次」这一条不是偷懒，是**防闪烁**：用户从 `{"a":1, "b":2}` 里横着拖选经过逗号时，
> 如果每次经过标点都清空，路径条会在 200ms 内闪三下 —— 比不做还烦。

### 3.3 路径语法（已拍板：JSONPath）

| 规则 | 写法 | 例 |
|---|---|---|
| 根 | `$` | 顶层标量 `123` → `$` |
| 成员 · 键名是合法标识符（`/^[A-Za-z_$][A-Za-z0-9_$]*$/`） | `.name` | `$.userName` |
| 成员 · 其他键名（含点、空格、中文、数字开头、空串） | `['...']` | `$['a.b']`、`$['中文']`、`$['1st']` |
| 数组元素 / tuple 元素 | `[i]` | `$.list[3]`、`$[0]` |
| 非字符串键（Python `{1: 2}`、Map 裸键） | 按 FR-A16 转成字符串后加引号 | `$['1']` |
| 键名内含 `'` 或 `\` | 反斜杠转义 | `$['a\'b']`、`$['a\\b']` |

**为什么中文走方括号**：`$.用户名` 在多数 jsonpath 实现里能跑，但在 Java DSL、部分 CLI 里会出错。
方括号形式是**所有实现都认**的交集写法 —— 复制的目标是「贴到哪里都能用」，不是「看起来最短」。

### 3.4 显示与复制

**位置**：判定条下方新增一条常驻「路径条」（`#pathBar`），**只在格式化 tab 显示**；切到转义/转换 tab 时隐藏并清空。

```
┌ 判定条： ● 标准 JSON        [来源▾]        （格式化 tab 下无目标选择器）
├ 路径条： $.data.list[3].userName        [数字]   [复制]
├ 输入区 …
```

| 项 | 规格 |
|---|---|
| 造型 | 与输出区同色系的「读数条」：等宽字体、凹进、高度 ~28px，不抢视觉 |
| 溢出 | 320px 下优先保**尾部可见**：溢出时中段省略 `$.data.list[…].userName`（CSS 做不到，需 12 行 JS，仅在 `scrollWidth > clientWidth` 时算一次） |
| 复制按钮 | 点击复制路径纯串（无引号、无首尾空白）；成功后按钮文案变「已复制」1.2s 后还原 |
| 双击路径文本 | 等价复制（`dblclick` 监听，**不 `preventDefault`** —— 文字被选中反而让用户看得见复制了什么） |
| 键盘 | 路径条 `tabindex="0"`，Enter / Space 复制 |
| 无障碍 | `role="status"` + `aria-live="polite"`；空路径时无播报 |
| 空 / 不可用态 | 占位文案 + 复制按钮 `disabled`，不显示任何「猜出来」的路径 |

### 3.5 降级与不可用

| 情况 | 表现 |
|---|---|
| 严格档语法错误（无 IR） | 输入区：`语法错误，无法定位路径` + 禁用复制。**输出区仍可用**（FR-D7 保留上次结果，那份结果有自己的 IR） |
| 来源格式 = Java 转义 | `该格式不支持路径定位`（原因见 §1.1，不做近似） |
| 输出语言 = Java 转义（目标为 java 时） | 同上 |
| 超时 / 文档 > 500k（FR-G4 档） | 输入区照常（复用已有 IR，零成本）；**输出区不提供**（二次解析成本高），显示 `文档过大，输出区不提供路径` |
| 嵌套超过 `MAX_DEPTH`（200） | 不崩；超出部分不可定位，保持上一次 |

## 四、需求条目（FR-P，EARS）

| ID | 类型 | 需求描述 |
|---|---|---|
| FR-P1 | **[E]** | 在格式化 tab 中，当用户将光标置于输入区或输出区的某个 key / value 上时，系统应显示该元素在当前文档中的路径。 |
| FR-P2 | **[U]** | 路径一律采用 **JSONPath** 语法：根为 `$`；合法标识符键用 `.name`；其余键用 `['...']`；数组元素用 `[i]`。 |
| FR-P3 | **[E]** | 当光标位置变化时（单击、双击、拖选、方向键移动），系统应以**光标位置**（拖选时取 head）重算路径，不得使用选区区间。 |
| FR-P4 | **[S]** | 当光标落在逗号、冒号、空白、缩进上，或落在不属于 IR 的文本上时，系统应**保持上一次**显示的路径，不得清空或闪烁。 |
| FR-P5 | **[U]** | 路径字符串必须由 `src/core/` 的纯函数从 IR 计算得出，**不得读取编辑器 DOM 文本**（与 AC-39「复制取程序产物」同一原则）。 |
| FR-P6 | **[O]** | 系统应提供「复制路径」按钮；复制内容为路径纯串，成功后给出短暂（≤1.5s）视觉反馈。 |
| FR-P7 | **[O]** | 双击路径文本应等价于点击复制按钮。 |
| FR-P8 | **[S]** | 当来源或输出格式为 Java 转义字符串时，系统应显式提示「该格式不支持路径定位」，**不得**给出近似路径。 |
| FR-P9 | **[U]** | 路径条仅在格式化 tab 可见；切出时隐藏并清空，切回时不恢复。路径与光标位置**不入 `storage.*`**（FR-H4 不变）。 |
| FR-P10 | **[U]** | 路径条的存在不得破坏 FR-S3：320 / 360 / 500px 三档下无横向滚动、无控件裁切。 |

> **FR-P3 的措辞很重要**：写「以光标位置为准」而不是「以选中内容为准」，
> 是因为用户拖选一整段时，那段可能是三个元素 —— 系统不可能给出「三个路径」，必须选一个锚点。
> head 是唯一符合直觉的选择（手停在哪就是哪）。

> **FR-P8 是本次的「不可实现，仅记录」条目**，按项目惯例写进 PRD 正文，
> 避免后人重复尝试用比例映射去糊 Java 转义的偏移。

## 六、Non-Goals（明确不做，防范围蔓延）

- ❌ **不做路径反查/跳转**：输入路径 → 高亮定位。看起来只差一点，实际要处理「非法路径」「多处匹配」「重复键」，是独立需求。
- ❌ **不做可点击跳转的「面包屑」**（每段可点、点了折叠父级）。v1.2 的工业仪表面板风格也不适合层级折叠动画。
- ❌ **不做重复键提示**：路径本身仍正确（指向键名），重复键属数据质量提醒，已由 FR-A6 的修正记录承担。
- ❌ **不做路径格式可切换**（点号 / jq / JSON Pointer 三选一）。一个格式 + 一个复制，先把口径统一；真有人要再加是纯增量。
- ❌ **不做 Java 转义格式的近似定位**（见 FR-P8）。
- ❌ **不把路径写进任何存储**，也不随「标签页」形态继承（光标位置本来就不继承）。
- ❌ **不新增权限、不引入依赖、不碰转换内核规则**、不改承载形态。

## 七、决策记录

### 已拍板（2026-10-26）

| # | 决策 | 选择 | 主要理由 |
|---|---|---|---|
| D-1 | 路径语法 | **JSONPath `$.a.b[0]`** | `$` 一眼看出是路径；可直贴 jsonpath 工具；与 jq（`.a`）区分清楚 |
| D-2 | 覆盖范围 | **输入区 + 输出区** | 用户多数时候盯着下面的美化结果读；只做输入会让「点了没反应」像 bug |
| D-3 | 显示位置 | **判定条下方常驻一条** | 全宽、空间充足、320px 可省略；切 tab 整体隐藏，不参与拥挤场景 |
| D-4 | 键/值口径 | 同一条路径，徽标区分 | 点 key 的意图就是「要这个字段」 |
| D-5 | 非元素落点 | 保持上一次 | 防拖选闪烁 |
| D-6 | Java 转义 | 不支持 + 明示 | 坐标系不可映射，错路径比没路径危险 |
| D-7 | 持久化 | 不落盘、不继承 | FR-H4 承诺不变；光标本就不继承 |

### 仍待确认（非阻塞，实现时按推荐值走）

| # | 问题 | 推荐值 |
|---|---|---|
| Q1 | 路径条是否顺带显示元素值预览（如 `= "张三"`）？ | **不做**。值预览会引入「长字符串截断」「敏感内容被截图」两个新问题，收益低于成本 |
| Q2 | 数组下标是否显示数组长度（如 `[3]/12`）？ | **不做**。信息密度换不来决策 |
| Q3 | 路径条在无路径时是否整体隐藏（而非占位）？ | **占位**。常驻条忽隐忽现会让下面两个编辑区跳动 |

## 八、迭代计划

## 九、风险与对策

| # | 风险 | 概率 | 对策 |
|---|---|---|---|
| R1 | **Span 语义没吃准**（end 是否含尾字符）导致点括号/引号时偏一个字符 | 中 | J1 第一件事就是用 3 条单测把它钉死，再写算法；不先写算法再猜 |
| R2 | **输出区二次解析拖慢**（500k 文档每次点击重解析） | 中 | J3 缓存 + 只在点击时算；超 T2（500k）直接降级为「不提供」 |
| R3 | **CM6 点击同一位置不触发 `selectionSet`** → 「点了没反应」 | 高 | J6 双挂 `mousedown`（已写入坑 20），并用一条 jsdom 测试锁住 |
| R4 | **老测试的精简 DOM 没有 `#pathBar`** → 既有 232 条测试大面积失败 | 高 | `DomRefs` 全部可选 + 可选链，与 `enlarge` 同款；改完先单独跑 `npm test` 再继续 |
| R5 | 多一行高度挤掉 320px 下的按钮（FR-S3 回归） | 中 | 路径条只在格式化 tab 出现（最拥挤的转义 tab 不受影响）；仍必须三档真机复验，AC-98 单列 |
| R6 | 用户在路径条上单击期待「跳转」 | 中 | 路径条 `title` 写明「点击复制按钮或双击复制」；不做跳转是明确 Non-goal |
| R7 | 中间省略自己实现出 bug（截断在多字节字符中间） | 中 | 按 Unicode 码点切（`[...str]`，与 FR-F4 字符计数同口径） |
| R8 | 路径与「类型覆盖」的 `/a/0/b` 口径混淆 | 低 | 两者用途不同（一个给人看、一个给内部匹配），代码分层：`path.ts` 只管展示，不复用 `makePath` 的输出 |
