## 一、起点与决策

2026-11-27，用户确认了独立的 7 屏改版样张（侧边栏格式化/转换/空态/转义/报错/更多菜单、
标签页格式化/转换/对比），并拍板两件事：

1. **侧边栏继续「底栏 chip + 更多菜单」**，不改成整排按钮横向滑动；
2. **两个颜色按 DSH 官方值保留**：浅色 tertiary `#81858C`、深色错误文字 `#F25A5A`，
   不采用样张初稿里为对比度调深的 `#6B7076` / `#FF9A9A`。

本迭代把样张从 `.workbuddy` 的静态案例落到 `src/ui/**`，并建立后续必须遵循的样式规范。

## 二、范围

### 做

- 令牌层：浅/深语义 token、0.5px 发丝线、反色主按钮、蓝色只给焦点/选中；
- 壳层：品牌块、浮起 tab、`本地处理`、判定条、路径条、双区头、两行底栏；
- 侧边栏：模式 chip（当前档位常驻可见）、更多菜单、图标下载、动作优先级；
- 状态：修正条、建议条、空态、输出空态、过期输出、类型面板、错误行；
- 浮层：对比浮层改为 1080×676 对话框、更多菜单、下拉菜单、搜索面板；
- 编辑器：CM6 `HighlightStyle` + CSS 变量，移除 `oneDark`；配对括号/行号/活动行/选区令牌化；
- 文档：样式规范、PRD v1.13、README、docs 索引、交付说明、9 张真机截图。

### 不做

- 不改 `src/core/**` 的解析/序列化与 `controller` 的状态机语义；
- 不改 Chrome 权限/隐私承诺（仍是 `storage` + `sidePanel`，零 host、零网络、零落盘）；
- 不新增功能；不重做 diff 算法（仍是同位置行级比较 + 400 行上限）；
- 不改低对比色的官方值（按用户决策）。

## 四、关键决策与理由

1. **保留旧 class/id**：测试、真机脚本和控制器契约都依赖它们；重构通过“同一选择器换样式”
   完成，避免大面积改选择器造成的回归。
2. **移动而不是复制菜单项**：复制会出现两套按钮、两份事件、两套 disabled/hidden 状态；
   移动保留 `DomRefs` 引用与监听，控制器无需感知菜单。
3. **深色兼容别名重绑**：`--bg: var(--dsw-...)` 在 `:root` 已求值，只改 body 的 `--dsw-*`
   不会重算；必须显式重声明，否则深色白底黑字。这是本轮发现并修复的真 bug。
4. **CM 高亮用 CSS 变量**：一套 HighlightStyle 同时服务浅/深，切主题不重建编辑器；
   `oneDark` 会接管底色，与令牌层冲突，移除。
5. **官方低对比值保留**：遵守用户决策；在规范 §3.2 明确记录 AA 取舍与外部分发前的复核条件。

## 六、遗留与下一步

- 对比浮层仍是同位置行级 diff，不是 LCS/token diff（FR-S8 范围）；
- 官方低对比小字（tertiary / 深色错误）在外部分发/过审前需复核；
- 更多菜单项暂无图标（移动按钮的契约优先）；
- 侧边栏宽度仍无 API；继续用「标签页」出口与首启宽度引导。
