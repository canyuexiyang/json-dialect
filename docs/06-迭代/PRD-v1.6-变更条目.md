## 零、为什么要改（定性结论）

格式化把文本整理干净之后，**最后一步仍然是人工**：把结果里的某个字段抄进代码/日志/接口断言时，
层级得靠数缩进。这一步没有被任何工具消掉，因为它需要一个「这段文本里的这个位置，在结构上是谁」的能力。

这个能力在本项目里**几乎是免费的** —— `ConvertResult.ir` 的每个节点都带 `Span{start,end}`，
而 `start/end` 直接取自 lexer 的 `Token.start/end`，就是**源文本字符偏移**。
换言之：偏移 → 节点 → 路径，只差一个纯函数。

| 方案 | 结论 |
|---|---|
| 用 `@codemirror/lang-json` 的语法树反查 | ❌ 只对 JSON 有效；来源是 Python / Map 时树完全不对 |
| 新增专用 parser | ❌ 重复劳动，且会与既有 parser 产生第二套坐标系 |
| **复用 IR 的 Span** | ✅ 四种来源里三种天然对齐，零新增解析 |

## 二、新增需求（编号 P = Path）

| ID | 一句话 | 依据 |
|---|---|---|
| FR-P1 | 光标落在 key/value 上 → 显示路径 | 需求主体 |
| FR-P2 | 路径统一 JSONPath，非标识符键退化为 `['...']` | 决策 D-1；交集写法保证「贴哪都能用」 |
| FR-P3 | 以**光标位置**为准，不用选区区间 | 拖选一节文本时系统只能给一个锚点，head 最符合直觉 |
| FR-P4 | 落在分隔符/空白/文末 → 保持上一次 | 防闪烁 |
| FR-P5 | 路径由 core 纯函数算出，不读 DOM | 与 AC-39 同源 |
| FR-P6 | 复制按钮 + 短暂反馈 | 用户明确要求 |
| FR-P7 | 双击路径文本复制 | 用户明确要求 |
| FR-P8 | Java 转义格式明示不支持 | 坐标系不可映射（见下） |
| FR-P9 | 仅格式化 tab 可见，不落盘不继承 | FR-H4 |
| FR-P10 | 不破坏 320px 可用性，溢出走中段省略 | FR-S3 |
| FR-P11 | 无内容时按钮禁用且不留「已复制」文案 | 自测发现的矛盾画面（见 §五） |

### FR-P8 为什么是「不做」而不是「做得差一点」

`parse/javaEsc.ts` 的处理顺序是 `unescapeJavaText()` → `lex(inner)` → `parseJson()`。
IR 的 Span 因此落在**解码后的文本**里：源码 `{\"a\":1}` 与解码文本 `{"a":1}` 长度不同。
任何按比例或按位置映射都会在嵌套时逐步漂移，最终指向**另一个字段**。

**错路径比没有路径危险** —— 用户会照着它去改代码。因此按项目惯例写成
「不可实现，仅记录」，避免后人重复尝试（同 FR-S5 的处置方式）。

## 三、新增验收（AC-89 ～ AC-104）

完整表格见 `PRD.md` §8.11。要点：

- **AC-89～AC-94** 内核定位（单测覆盖，含特殊键名转义）
- **AC-95～AC-97** 复制链路与 tab 可见性
- **AC-98** 三档宽度 —— **jsdom 测不了**，由 `tools/v14-verify.mjs` 在真实 Chrome 量测 + 人工目测
- **AC-99～AC-101** 降级态与两侧口径一致
- **AC-102** 性能（实测 500k 文档中位 **0.51ms**，预算 16ms）
- **AC-103** 证明路径不取 DOM：**故意把路径条文本改脏**，剪贴板仍应为真实路径
- **AC-104** 零落盘

## 四、决策记录

| # | 决策 | 选择 | 理由 |
|---|---|---|---|
| D-1 | 路径语法 | JSONPath `$.a.b[0]` | `$` 一眼看出是路径；与 jq 的 `.a` 区分清楚 |
| D-2 | 覆盖范围 | 输入区 + 输出区 | 用户多数时候盯着下面的美化结果读；只做输入会让「点了没反应」像 bug |
| D-3 | 显示位置 | 判定条下方常驻一条 | 全宽、可省略；输出区标题行在 320px 下要与统计抢位置 |
| D-4 | 键/值口径 | 同一条路径 + 类型徽标 | 点 key 的意图就是「要这个字段」 |
| D-5 | 非元素落点 | 保持上一次 | 防拖选闪烁 |
| D-6 | Java 转义 | 不支持 + 明示 | 坐标系不可映射，错路径更危险 |
| D-7 | 持久化 | 不落盘、不继承 | FR-H4；光标本就不继承 |

### 自测发现的两个问题（都修了）

1. **禁用态残留「已复制」**：复制反馈的 `setTimeout` 与「路径变为不可用」竞争，
   出现「路径条写着报错、按钮却写着已复制」的自相矛盾画面。改为统一的
   `resetPathCopyLabel()`，并在禁用/清空时调用。
2. **建议条溢出（存量缺陷）**：`renderSuggestion` / `renderPrefixHint` 把提示条
   插进了 `.status`（`inline-flex` 且不换行），360px 下第二个按钮被裁掉右半边。
   这是 v1.0 起就有的问题，需要「报错 + 未锁定来源 + 窄侧边栏」三个条件同时成立才显形，
   所以历次三档宽度验收都没碰到。改为挂在 `.toolbar` 之前，成为整宽独立一条，
   并在真机脚本里新增断言锁住。

## 六、Non-goals（本版明确不做）

- ❌ 路径反查/跳转（输入路径 → 高亮定位）
- ❌ 可点击的面包屑（逐段折叠）
- ❌ 重复键提示（路径本身仍正确，重复键由 FR-A6 修正记录承担）
- ❌ 路径格式可切换（点号 / jq / JSON Pointer）
- ❌ 元素值预览、数组长度标注
- ❌ Java 转义的近似定位
