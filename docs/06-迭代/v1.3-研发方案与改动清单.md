## 1. 为什么必须换形态（复述结论，作为改造依据）

当前 `manifest.json` 声明 `action.default_popup`。Chrome 对 popup 的生命周期有硬性规定：
**页面失焦即销毁渲染器**。所以「切标签 → 回来内容全丢」是规范定义的必然行为，代码拦不住。

想「用户手动关闭才真关闭」，唯一路径是换一个渲染器不被销毁的承载形态。

| 承载形态 | 切标签后 | 手动关闭 | 宽度 | 结论 |
|---|---|---|---|---|
| popup | ❌ 销毁 | 自动 | 720px 固定 | 淘汰 |
| **sidePanel** | ✅ 文档存活 | ✅ | 320–360px | **采用** |
| **独立标签页** | ✅ | ✅ 手动关 tab | 整窗 | **采用**（已实现，需强化） |

**关键约束**：`sidePanel` 宽度物理下限 320px（Chromium `kSidePanelMinWidth`），
与当前 `.app` 硬编码的 `width: 720px` 正面冲突。**这是本次主要工作量。**

## 3. 目标架构

> ⚠️ **2026-10-08 补充：popup 已拍板彻底删除**，本节架构随之调整。
> 删掉 popup 的直接后果：**必须引入 service worker**（详见 §4 C1）。

```
              ┌─────────────────────────────────────┐
              │  单一 DOM 模板（v1.3-4 合并而来）      │
              │  .app + .app--panel / .app--large    │
              └──────────────┬──────────────────────┘
                             │
        ┌────────────────────┼────────────────────┐
        ↓                    ↓                    ↓
   panel.html            app.html            background.ts
   侧边栏主形态            独立标签页形态        service worker
   SurfaceKind='panel'   SurfaceKind='tab'    「仅注册面板行为」
   窄屏响应式              整窗 + session 继承    无其他逻辑
        │                    │
        └──── window.open ────┘  （保持 AC-49，禁 chrome.tabs.create）

   ✗ popup.html  /  src/ui/popup.ts  —— 整条链路删除
```

**形态枚举**（替代死掉的 `isPage`）：

```ts
type SurfaceKind = 'panel' | 'tab';
```

选它的理由：布尔 `isPage` 无法表达第三态，且 `false` 语义模糊（是 popup 还是 panel？）。

### 为什么必须引入 service worker

删掉 `default_popup` 后，**点击工具栏图标默认什么都不发生**（Chrome 规范：若无 `default_popup`，
点击触发 `action.onClicked`；若连 `onClicked` 都没监听，则无任何反应）。
项目当前是**纯页面扩展、无 service worker**，所以必须新增一个。

该 worker 只需注册面板行为，**不承载任何业务逻辑**。

**根因**：`.app` 写死 720×600 + `overflow:hidden` → 侧边栏下溢出内容被**直接裁掉**。

// 放进回调或 await 之后会漏事件（项目已有同类教训：坑 9）

  chrome.sidePanel.setPanelBehavior({ openPanelOnActionClick: true }).catch(() => {});

**两个必须写对的点**（写错症状均为「点了没反应」，极难自查）：

| 坑 | 正确 | 错误后果 |
