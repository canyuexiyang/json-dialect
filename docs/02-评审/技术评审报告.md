## 一、🔴 硬冲突（阻塞级）

### C-1｜FR-F6「放大」与 FR-H2「禁 tabs 权限」直接冲突

**问题**：PRD §FR-F6 要求「点击放大 → 独立浏览器标签页打开完整页面版本，并继承输入文本、来源判定、类型覆盖状态」。常规实现是 `chrome.tabs.create({ url: chrome.runtime.getURL('app.html') })`，但 **`chrome.tabs.create` 需要 `tabs` 权限**，而 FR-H2 明文禁止声明 `tabs`——两条需求不可能同时满足。

**结论与方案**：改用 **扩展页内 `window.open(chrome.runtime.getURL('app.html'))`**。

- 扩展页（popup.html / app.html）脚本中调用 `window.open` **不需要任何权限**，也不触发 host 权限审查；
- 打开的是扩展协议页面，天然满足 FR-H5（无外部资源）；
- 代价：无法拿到 tab 句柄做后续通信（本项目不需要）。

**状态继承方案**（同时解决"输入文本不能落盘"的矛盾）：

| 方案 | 是否落盘 | 结论 |
|---|---|---|
| URL query / hash 传参 | 否，但受 URL 长度限制（大文本必崩） | ❌ 仅作兜底 |
| `chrome.storage.local` | **是** → 违反 FR-H4「输入内容零落盘」 | ❌ 禁用 |
| **`chrome.storage.session`** | **否（纯内存，浏览器关闭即清空，Chrome 102+）** | ✅ **采用** |

**需修订的条目**：
- **FR-F6**：明确「通过扩展页内 `window.open` 打开，不使用 `chrome.tabs` API」；
- **FR-H4**：增加「跨页面传递的会话态（输入文本、来源判定、类型覆盖）使用 `chrome.storage.session`，仅存于内存；持久化的界面偏好仍只允许 `chrome.storage.local`」。

> 附带收益：`chrome.storage.session` 在弹窗关闭后仍保留（浏览器会话内），可顺带解决 FR-E9「弹窗关闭后模式重置」的体验问题——见 D-6。

### C-2｜§7.1「Java 转义字符串」打分信号会误判合法 JSON

**问题**：§7.1 给「存在 `\"` 转义序列 → +4/次」，但 FR-C2 的判定条件是「**整段被双引号包裹**且内部双引号被 `\"` 转义」。两者不一致。后果很直接：

```json
{"msg": "he said \"hi\""}
```

这是**合法标准 JSON**，按 §7.1 会命中 `\"` × 2 = **+8**，压过 JSON 自己的 +5，被误判为「Java 转义字符串」，然后被反转义一次变成非法文本。

**方案（二选一，推荐 A）**：

- **A（推荐）**：Java 转义信号加**结构前提**——必须满足「去空白后首字符是 `"` 且末字符是 `"`（整段被包裹）」才计分，且计分改为 **+4（存在即计一次，不按次数累加）**；
- **B**：保留按次累加，但要求**整段被包裹**且 `\"` 出现 ≥ 2 次，且总分需超过 JSON 信号 **5 分以上**才翻转判定。

同时对打分算法做**两处通用加固**（一并解决长文本偏置）：

1. **所有信号改为「存在性计分 + 次数上限封顶」**（每类信号最多计 2 次），避免 200 个单引号（+400）压倒一切其他信号；
2. **打分器必须复用 lexer 的 token 流**，不得另写一套引号状态机——否则打分判定与解析器对"什么是字符串"的理解会漂移，这是这类工具最经典的 bug 源。

**需修订的条目**：§7.1 信号表 + FR-B3（补充"打分消费 token 流"的实现约束）。

## 三、🟡 设计建议（不阻塞，但强烈建议采纳）

### D-1｜「三层解析」在实现上应塌缩为「一次 token 化 + 双模式」——本次评审最重要的建议

PRD §FR-D1 描述的是**三次解析**（严格 → 宽松修复 → 报错）。若按字面实现为"对文本做多轮重写再解析"，会踩三个坑：

1. 6 类修复自由组合 → **修复顺序依赖**，同一输入可能得到不同结果；
2. 每轮重写文本后，**行号列号会漂移**，FR-D6 要求的"精确行列定位"难以保证；
3. 性能上要跑 2–3 遍全量解析。

**建议实现**：lexer 一次扫描产出 token 流，parser 以 `strict` 开关消费同一份 token 流。

```
lexer(text)  →  Token[]   // 每个 token 带 {line, col, raw, marks[]}
                           // marks 记录该 token 生成时触发的"容忍修复"
parse(tokens, fmt, {strict:true})   → 成功即输出，fixes = []
parse(tokens, fmt, {strict:false})  → 成功即输出，fixes = 所有 token.marks
两层都失败 → 用失败 token 的 line/col 直接报错（无需第三次解析）
```

- **严格模式**：单引号字符串 → 错误；裸键名 → 错误；末尾逗号 → 错误；`#` → 错误；栈未闭合 → 错误。
- **宽松模式**：上述 5 项全部放行，并在对应 token 上打 mark（`{type:'quote_fixed', line, col, before, after}`）。
- **修复记录天然来自 token 的 line/col** → FR-D5 的「第 N 行：涉及片段 → 修正动作」直接可得，无需额外维护位置映射。
- **报错定位天然精确** → 第 3 层不是"再解析一次"，而是把第 2 层的失败 token 位置格式化输出（这也让 §7.4 的流程图在实现上少一层）。

> 附带修正：FR-D5 的修正记录建议**补列号**——单行压缩输入（如 `[1,2,]`）只有行号没有列号时，用户无法定位。

### D-2｜类型下拉框不要嵌进只读编辑器——改用「值切片渲染 + 行内 DOM 控件」

FR-C6 要求输出区每个值旁有类型下拉，FR-F9 又要求输出区只读。在 CodeMirror 只读编辑器里用 `Decoration.widget` 挂交互控件技术上可行，但会带来一串麻烦：光标与 atomic range 处理、复制时 widget 文本混入、DOM diff 与重建、只读模式下点击事件拦截。

**建议方案**：输出区不承载交互，改为**结构化渲染**：

- 序列化器输出时，同时产出「文本 + 值位置索引」（`{path, line, col, start, end, inferredType}`）；
- 输出区用只读 CodeMirror 渲染纯文本（高亮照旧），**类型下拉以绝对定位的行内 DOM 浮层叠在对应值右侧**（按 line/col 换算坐标，或直接用 CM 的 `Decoration.mark` 拿到的屏幕位置）；
- 值数量 > 50 时自动切 FR-C11 的「类型调整面板」。

**必须配套的验收**（建议新增 **AC-39**）：**「复制」「下载」的内容必须取自 IR 序列化结果，不得取自编辑器 DOM**，确保交互控件绝不污染输出内容。这一条不写进去，迟早会出"复制出来多了一堆 ▾"的事故。

### D-3｜FR-G6「3 秒超时中止」在同步解析下无法实现 —— 用 deadline checkpoint 代替 Worker

纯函数同步解析器无法从外部中断。两个可选解：

- ❌ **Web Worker**：需处理 MV3 extension_pages CSP 的 `worker-src`、消息序列化、以及"Worker 里也要 bundle 一份解析器"，对 500 行文本属于杀鸡用牛刀；
- ✅ **deadline checkpoint（推荐）**：`parse(tokens, fmt, {deadline})`，在 token 消费循环里**每 4096 个 token 检查一次 `Date.now()`**，超时抛 `TimeoutError`。

它保持纯函数（deadline 是入参）、可在 Node 里单测（传一个已过期的 deadline 即断言抛错）、零 CSP 风险。建议把这条写进 FR-G6 的实现说明。

### D-4｜关闭高亮不要重建编辑器 —— 用 CodeMirror Compartment 动态卸载

FR-G3 要求输入 10 万–50 万字符时关闭语法高亮。若实现为"卸载 CodeMirror 换 textarea"，会丢失光标位置、滚动位置、undo 栈，体验断层。

**建议**：始终保留同一个 `EditorView`，把 `highlightExtension` 放进 `Compartment`，降级时 `dispatch({effects: compartment.reconfigure([])})`。关高亮 ≈ 关一个扩展，状态全保留。

### D-5｜评测与交叉验证：把「Python 真值校验」做成脚本，别靠肉眼

FR-A10 / AC-31a 都要求输出可被 `ast.literal_eval` 求值。本机有 Python，建议直接做成门禁：

```
tools/verify_with_python.py    # 读 samples/*.out.py，逐条 ast.literal_eval，失败即退出非 0
npm run test:golden            # vitest 跑 samples/ 30 条黄金样本
npm run test:prop              # fast-check 属性测试（见下）
```

**属性测试**（对应 §10 R1 的缓解措施 ③）：随机生成 Python 字面量 → 转 JSON → `JSON.parse` → 反转回 Python → `ast.literal_eval` → 断言与原始结构等价。这条能覆盖人脑想不到的引号/转义组合，是本项目性价比最高的一道防线。

### D-6｜FR-E9「模式不持久化」与 FR-H4「界面偏好可持久化」自相矛盾

FR-H4 明确允许界面偏好写 `chrome.storage.local`，FR-E9 却要求"弹窗关闭后重置为格式化，不做持久化"。二选一，建议**改为持久化**（弹窗是高频开关场景，每次都重置很烦），且它完全在 FR-H4 允许范围内。同时把"分栏比例"（FR-F8）也一并持久化。

### D-7｜中间表示（IR）与类型覆盖路径的落地定义

FR-C8 说覆盖绑"结构路径"但没定义路径语法。建议固化：

```
path = "/" + 段（对象用 key，数组用 index）  →  /user/age  、 /tags/0  、 /list/2/name
```

IR 节点定义建议：

```ts
type JVal =
  | { k: 'obj'; entries: Array<{ key: string; val: JVal; span: Span }>; span: Span }
  | { k: 'arr'; items: JVal[]; span: Span }
  | { k: 'str'; value: string; span: Span }
  | { k: 'num'; raw: string; span: Span }      // FR-A11：只存原始 token
  | { k: 'bool'; value: boolean; span: Span }
  | { k: 'null'; span: Span };

type Span = { start: number; end: number; line: number; col: number };
```

`num.raw` 存原始 token 是实现 FR-A11 的关键：**解析器全程不调用 `Number()`**，`12345678901234567890`、`1.0`、`1e5` 全部原样透传，精度问题从根上消失。

### D-8｜统计条口径与转义表需固化

- **FR-F4 字符数**：建议按 **Unicode 码点**（`[...str].length`）而非 UTF-16 code unit，否则含 emoji 的文本计数会偏大，用户会以为工具算错了。行数 = `\n` 数量 + 1。
- **转义表**：JSON 侧字符串内 U+0000–U+001F 必须转义（`\u0001` 形式），U+2028/U+2029 建议一并转义（避免贴进 JS 源码时出问题）；Python 侧用 `\x01` / `\u2028`。FR-A12 建议补一张对照表。
- **FR-A7 不转义中文** 与上面不冲突（中文属 BMP 可打印字符），保持原样。

## 五、落地架构方案

### 5.1 分层

```
src/core/                    ← 纯函数，零浏览器 API，可在 Node 直接单测（FR-A 模块约束）
  lexer.ts                   统一 tokenizer：产出 Token[]（含 line/col/raw/marks）
  detect.ts                  来源打分（消费 Token 流，§7.1）
  parse/
    json.ts  python.ts  javaEsc.ts  mapText.ts     四形态 parser，共享 Token 流
  ir.ts                      JVal 中间表示 + Span + path
  serialize/
    toJson.ts                2 空格 / 压缩（FR-E1/E3）
    toPython.ts              引号选择算法（§7.2）+ 转义表
  fixLog.ts                  token.marks → 修正记录（FR-D4/D5）
  errors.ts                  行列定位 + 原因分类（FR-D8）
  index.ts                   convert(input, opts) → { ir, source, fixes, error, stats }
src/ui/                      ← 浏览器侧，仅此层可碰 DOM / chrome.*
  popup.ts  app.ts          弹窗与放大页（共用同一套 UI 组件）
  editor.ts                 CM6 封装 + Compartment 动态高亮（D-4）
  typeWidgets.ts            类型下拉浮层（D-2）
  clipboard.ts              三级降级链（FR-E4–E6）
  download.ts               Blob URL + <a download>（FR-E7，无需 downloads 权限）
  sessionState.ts           chrome.storage.session 读写（C-1）
tests/
  unit/  golden/  prop/      vitest
samples/                     30 条真实样本（§9.1）
tools/verify_with_python.py  ast.literal_eval 交叉校验（D-5）
```

### 5.2 统一转换流程（把判定、三层、回退串成一条线）

```
输入文本
  │
  ├─ lexer(text) ──────────────► Token[]      // 一次扫描，位置信息固定
  │
  ├─ detect(Token[]) ──────────► 候选排序      // 手动锁定则跳过
  │
  └─ for fmt of [ 首选格式, ...回退格式 ]:     // 回退顺序见 G-1（FR-B11）
        parse(tokens, fmt, strict=true)   成功 → 输出，fixes=[]         「已解析」
        parse(tokens, fmt, strict=false)  成功 → 输出 + 修正记录         「已修复」
     全部失败 → errors.from(lastFailedToken)                            「解析失败」
```

关键点：**四形态 parser 消费的是同一份 Token 流**，所以"回退尝试其他格式"几乎零额外成本（不用重新扫描），这让 G-1 的全格式回退可以廉价实现。

### 5.3 manifest 权限清单（评审确认版）

```json
{
  "manifest_version": 3,
  "permissions": ["storage"],
  "action": { "default_popup": "popup.html" }
}
```

- ✅ 无 `host_permissions`、无 `tabs` / `activeTab` / `scripting` / `cookies` / `webRequest`（FR-H2）
- ✅ 无 `downloads`（FR-H6 —— 扩展页内 `URL.createObjectURL` + `<a download>` 可用，实测确认这一条**不需要** `downloads` 权限；仅在需要"静默保存到指定目录"时才需要，本项目不做）
- ⚠️ `storage` 用于界面偏好（`local`）与跨页会话态（`session`），两者均不含输入/输出内容（FR-H4）
