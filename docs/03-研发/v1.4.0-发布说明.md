# v1.4.0 发布说明（2026-10-26）

本次为**功能增量版本**：格式化 tab 新增「元素路径定位」—— 点一下 JSON 里的 key 或 value，
直接拿到它的 JSONPath 并可一键复制。承载形态、转换内核、权限承诺全部不变。

## 主要变化

- **路径定位（FR-P1～P11）**：光标落在某个 key / value 上 → 判定条下方显示 `$.data.list[3].userName`；
  点 key 与点 value 得到**同一条路径**，用类型徽标（键 / 字符串 / 数字 / 布尔 / null / 数组 / 对象）区分。
- **三种复制方式**：点「复制」按钮、双击路径文本、在路径条上按回车。
- **不闪断**：光标落在 `,` `:` `=` 空白或文末时**保持上一次**路径 —— 横拖选字时不会连闪。
- **输入区与输出区都支持**，两侧口径一致；输出区对**显示中的文本**二次解析（带缓存）。
- **键名退化规则**：非合法标识符键走方括号 —— `$['a.b']`、`$['中文']`、`$['a\'b']`。
- **Java 转义格式明示不支持**：`parseJavaEsc` 先解码再解析，Span 落在解码空间，
  与源码偏移不是同一坐标系。按比例映射会给出**错路径**，宁可不给（FR-P8，按
  「不可实现，仅记录」留档）。
- **边界**：只在格式化 tab 出现，切出即隐藏并清空；不写任何存储、不随标签页继承（FR-H4 不变）。
- **零新增依赖、零新增权限**：`src/core/path.ts` 是唯一新增模块，纯函数。

## 自测中发现并修复

| # | 问题 | 性质 |
|---|---|---|
| 1 | 路径条进入禁用态后仍残留「已复制」文案，出现「上面写着报错、按钮写着已复制」的矛盾画面 | 本次新增功能的反馈竞态（FR-P11） |
| 2 | 报错时的「可尝试手动切换来源格式」建议条在 360px 下第二个按钮被裁掉右半边 | **存量缺陷**（v1.0 起）：提示条被插进 `.status`（`inline-flex` 不换行），需「报错 + 未锁定来源 + 窄侧边栏」三条件同时成立才显形，故历次三档宽度验收未碰到。改为挂在 `.toolbar` 之前成为整宽独立一条，并在真机脚本新增断言锁住 |
