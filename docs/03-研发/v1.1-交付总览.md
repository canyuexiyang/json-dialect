## 三、四个已确认缺口的处置

| 缺口 | 症状 | 处置 | 状态 |
|---|---|---|---|
| **F1** | 日志前缀 `2024-01-01 12:00:00 INFO {"a":1}` → 输出只剩前缀，状态却报 `fixed` | `engine.ts` 尾部残留一律报错；转换 tab 提供一键「剥离前缀重试」 | ✅ 已消灭 |
| **F2** | JSON Lines `{"a":1}\n{"b":2}` → 只出第一个，状态 `fixed` | 新增 `multiple_values` 错误：一次只处理一个值 | ✅ 已消灭 |
| **F3** | `\uFEFF{"a":1}` 被误判 java 来源 | lexer 跳过 BOM（不改写 text，避免 start 偏移漂移） | ✅ 已修 |
| **F4** | `outputLangFor(src)` 硬编码，粘 JSON 只想格式化却被强制转 Python | 目标与来源解耦：`TargetFormat` + `sameTarget` + `outputLangFor(target)` | ✅ 已解耦 |

**F1/F2 根因复核**：`engine.ts` 宽松模式无条件忽略尾部残留，且用 `trailing_comma`
谎报「已忽略整段内容」。`lexer.ts` 里早定义好的 `tail_ignored` 从未被使用 —— 现已改由
`trailing_content` / `multiple_values` 两个明确错误类型接管。

## 六、自写错的断言（复盘，非产品 bug）

1. AC-55 错误列应为 **8**，不是 7（列从 0 起算，不要把 token 起点当列号）。
2. AC-57 的验收点是 `source === 'json'`，输出方向仍由来源推导 —— 不要顺手把输出也断言成 json。
3. FR-K1 严格档要挡的是**自动修复**，不是来源识别 —— `detect` 把 `{'a': 1}` 判为 python 是正确的。
