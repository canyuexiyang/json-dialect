---

## 一句话

**用户抱怨的「切标签页回来内容全丢」不是 bug，是 Chrome 对 popup 的机制定义**——
popup 渲染器在页面失焦时被销毁，代码拦不住。v1.3 换承载形态解决它，
主要工作量不在 API 接入，而在**布局响应式**（侧边栏最窄 320px vs 原先写死 720px）。

## 隐私口径（对外承诺）

| 项 | 状态 |
|---|---|
| 权限 | `["storage", "sidePanel"]`，**零 host 权限** |
| `sidePanel` 性质 | **非host 权限**。Chrome 官方明示侧边栏无需 host 权限即可展示 UI，不授予任何读取页面数据的能力 |
| 网络能力 | **零**。无 `fetch` / XHR / `sendBeacon`，字体本地内嵌 |
| 输入内容 | **零落盘**。`storage.local` 只写界面偏好，`storage.session` 只做一次性交接且读后即清 |

> ⚠️ **最易误解的一点**：侧边栏文档长期存活 ≠ 内容落盘。
> 内容存活是因为**文档没被销毁**，不是被写进了存储。FR-H4 承诺完全不变。
