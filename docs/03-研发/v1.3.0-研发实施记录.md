## 二、几个必须写对的点（写错症状都是「点了没反应」）

| 坑 | 正确写法 | 写错的后果 |
|---|---|---|
| 面板行为属性名 | `openPanelOnActionClick` | 写成 `openPanelOnActionIconClick` → 同步 TypeError，**静默中断整个 worker** |
| worker 监听器位置 | **模块顶层同步注册** | 放进回调或 await 之后 → MV3 worker 30s 回收后漏事件（项目同类教训：坑 9） |
| 面板作用域 | `windowId`（窗口级） | 用 `tabId` → 面板只属于那一个 tab，切 tab 即消失，**症状与 v1.2 一模一样** |
| `default_popup` | 必须删除 | 与 `setPanelBehavior` 互斥，popup 优先级更高会顶掉面板行为 |
| worker 输出文件名 | 固定 `background.js`，无哈希 | MV3 按 manifest 路径加载，哈希名会导致加载失败 |
| `.ts` 后缀 | 输出 `.js` | `chrome-extension://` 下 `.ts` 的 MIME 判定不可靠 |

这六条已全部写成单测断言（见 §四）。

## 三、实施中发现并修掉的两个真 bug

### 1. 标签页形态丢失输入内容（功能级）

重构 `app.ts` 时写成 `app.init('', toInherited(session))` ——
`initialInput` 传了空串。但 `InheritedState` **不含输入文本**（它走 `initialInput`），
于是标签页形态下 tab 状态、来源判定都继承了，唯独输入内容空白。

**症状极具欺骗性**：整体看起来是「继承生效了」，只有内容是空的。
纯靠读代码很难发现，是靠真机脚本断言 `inherited.input` 抓到的。

**修法**：`app.init(session?.input ?? '', ...)`。**已加单测锁定**（`readFlexGrow` 旁的不变量）。

### 2. splitter 拖拽在真实高度下会把输出区压没

原实现 `ratio = clamp(dy / rect.height)` 后写 `style.flex = 0.5 + ratio`，
但 `.pane` 是 `flex:1 1 0` + `min-height:0`，**可以被压到 0**。
窄侧边栏（竖长但总高有限）下尤其容易触发。

**修法**：三处一起改 ——

1. CSS `.pane { min-height: 72px }`
2. `applySplit()` 用 `setProperty` 写 flex 并同步写 min-height 兜底
3. `rect.height || clientHeight` 双兜底（jsdom 下两者都是 0）

同时补 `clearSplit()`（`removeProperty` 显式清除内联 flex ——
内联样式优先级高于样式表且无法靠切形态自动重置）。

## 四、新增的 23 条防回归断言

`tests/acceptance/v13-surface.test.ts` —— **不测「功能对不对」，只钉死最容易写错的地方**：

| 组 | 条数 | 钉住什么 |
|---|---|---|

| service worker | 3 | 属性名字面量、`addListener` 在顶层（缩进检查）、**代码中零 `tabId`** |
| popup 已删除 | 3 | 源文件不存在、vite 入口不引用、入口代码零引用 |
| 单模板 | 4 | 两形态 class 正确、`app--large` 与放大按钮互斥、**两形态 tabbar DOM 顺序一致**、引用全部可解析 |
| splitter | 4 | 方向键微调、比例钳制、Home/End 直达两端、min-height 兜底、`is-dragging` 增删 |
| 隐私口径 | 2 | 「零落盘」未被承载形态改写 |
| SurfaceKind | 2 | `isPage` 已消失、两态均被接受 |

**两条写断言的方法论教训**（都实际踩到了）：

1. **断言关键词不能出现在注释里**。「controller 不再含 isPage」若用全文匹配，
   会因为解释性注释里解释了这件事而永远失败。
   **一旦失败就没人敢信的断言等于没有断言。** 做法：`readCode()`剥掉注释行再匹配。
2. **jsdom 会把 `style.flex = '0.95'` 归一化成 `'0.95 1 0%'`** ——
   断言不能直接 `Number()`（得 NaN），要取第一段。

### 脚本本身踩的三个坑（已记入 README）

1. **`evaluateOnNewDocument` 会把函数序列化后注入，闭包变量全部丢失** ——
   外部变量必须先用一段字面量脚本写进 `window`。首版因此报 `BASE is not defined`。
2. **模拟 `chrome.storage` 必须遵守真实 API 形状** —— `get(key)` 返回 `{ [key]: value }`，
   不是 `value`。首版直接返回 value，导致消费方 `got[KEY]` 取到 undefined，
   症状只是「静默不继承」。
3. **`storage.session` 必须跨JS 上下文共享** —— `window.open` 出的新页是独立上下文，
   用页面内存模拟会永远测不出继承。用 `localStorage` 模拟（同源跨页共享）。

## 发布前修订（2026-10-08 深夜，真机实测反馈）

真机加载产物后用户报了两个问题，一轮修完，**测试 220 → 232，全部绿**。

### 问题 2（真 bug）：点「标签页」后侧边栏不关，屏幕上两个实例

v1.3 只做了「开」，没做「关」。修法（`src/ui/sidePanel.ts` 新文件）：

1. 优先 `chrome.sidePanel.close({ windowId })` —— 官方 API，但 **Chrome 141+ 才有**。
   `windowId` 走 `chrome.windows.getCurrent()` 取，**该方法不需要任何 manifest 权限**
   （只有读 `Window.tabs` 才要 `tabs`），权限承诺不变。
2. 兜底 `window.close()` —— 侧边栏本身是扩展页面，可自关（Chromium 官方邮件组推荐做法）。
3. 全程 try + 超时兜底；旧版无 `close()` 时必须**先判存在再调**，否则同步抛错连兜底都跳过。
4. ⚠️ 非扩展上下文（jsdom 测试）**不得调 `window.close()`** —— 它会把整个 window 标记为
   closed，污染同一测试文件后续用例。前置判断：连 `sidePanel` 命名空间都没有就不是侧边栏。

端到端验证：`tools/v13-verify.mjs` 的 stub 补了 `windows.getCurrent` 与 `sidePanel.close`，
点「标签页」后断言收到 `{ windowId: 1 }`。**第一轮跑出 `closeArgs: None`，
根因是 stub 漏了 `chrome.windows`** —— 真机上它无权限可用，stub 不补就会静默走兜底。

### 问题 1（Chrome 硬限制，不是 bug）：侧边栏太窄，想要 1/3

查证结论（Chrome 官方文档 + 多方资料交叉确认）：

- `chrome.sidePanel` 的 `PanelOptions` 只有 `enabled` / `path` / `tabId`，**没有 width**
- 宽度由浏览器 UI 层控制：默认约 360px、最小硬底约 320px，**只能用户手动拖边缘**
- 扩展既不能设置宽度，也不能让它随窗口按比例自适应 → **「默认占 1/3」做不到**

落地方案（用户拍板：保持侧边栏 + 一键升级）：

- 新增**宽度引导条**（`#widthHint`，只在侧边栏形态渲染）：说明宽度由 Chrome 控制、
  可拖边缘调宽、需要更大空间点「标签页」。首次显示，点「知道了」写入
  `prefs.hintWidth`（界面偏好，不违反 FR-H4），此后不再出现
- 配合问题 2 的修复，「觉得窄 → 点一下 → 整屏」路径闭环
- README 明确写入这条限制（有防回归断言钉着，防止口径被改丢）
