## 二、复核后修正的两处判断

1. **N01 不能把闸门下沉到 `run()`**：`renderOversizeHint()` 的「仍要转换」按钮与底部「转换」按钮也直接调 `run()`，
   简单下沉会把显式入口一起锁死。真实成因是 `setInput()` → `in.setDoc()` → `onChange` → `schedule()` 已拦截并挂出提示，
   紧随的 `run()` 在 `clearOversizeHint()` 里撤掉提示且不复位 `oversize`。
   **正解**：抽 `guardOversize(text)` 供 `schedule()` / `setInput()` / 首屏继承共用，显式入口仍直接 `run()`。
2. **N11 与 N06 从 P1 升 P0**：`app.ts` 注释自称「同步段优先」，`await consumeSession()` 却仍排在 `mountShell()` 之前，
   是历史 P0 事故（storage Promise 永不 settle → 界面点不动）在放大页入口的重演；
   `collect()` 给 bool/null 填 `raw:''` 导致类型覆盖静默产出空串，属结果正确性缺陷。
