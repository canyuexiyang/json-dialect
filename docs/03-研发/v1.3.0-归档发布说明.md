## 一、本次改了什么

事项「v1.3.0 · 承载形态重构：侧边栏 + 独立标签页」（任务树 rKzG1n，9/9 子任务完成）。

**起因不是 bug，是机制。** v1.2 用 `action.default_popup` 承载主界面，而 Chrome 对 popup
的硬规定是**渲染器在页面失焦的那一刻被销毁** —— 「切标签页回来内容全丢」拦不住。
唯一出路是换承载形态：**sidePanel（主）+ 独立标签页（空间拓展）**，popup 整条链路删除。

**承载形态变更，`src/core/` 一行未改。**

## 三、产物归档

### 构建产物（`dist/` 随代码入库）

```
dist/
├─ manifest.json          version 1.3.0，permissions ["storage","sidePanel"]
├─ panel.html             侧边栏入口（主形态）
├─ app.html               独立标签页入口
├─ background.js          MV3 service worker（固定名、无哈希）
├─ icons/                 3 个（16/48/128）
└─ assets/
   ├─ panel-*.js          侧边栏 chunk
   ├─ app-*.js            标签页 chunk
   └─ shell-*.js / .css   公共 chunk（单一 DOM 模板）
```

`popup.html` / `popup-*.js` 已彻底消失。worker 产物**必须固定 `background.js`**：
`.ts` 后缀在 `chrome-extension://` 下 MIME 判定不可靠。

### 发布附件

`json-dialect-dist-v1.3.0.zip`（240,511 B），根目录即 `manifest.json`，可直接加载。
比 v1.2.0 的 240,832 B 略小 —— popup 链路删掉了，侧边栏复用同一套 chunk。

打包后**解压到临时目录独立校验**（不只信 `dist/` 本身）：

- 声明的 `panel.html` / `background.js` / 3 个图标全部存在；HTML 引用的每个资源都真实存在
- `panel.html` 挂 `app--panel`、`app.html` 挂 `app--large`，各自入口指向自己的哈希 chunk
- worker 含 `openPanelOnActionClick` + `onInstalled` + `onStartup`，**无 `tabId`**
- 零 `host_permissions`、零 `default_popup`、零 popup 标识符、零外部 URL

## 四、发布前真机反馈修掉的问题

产物真机实测后用户报了两个问题，一轮修完，测试 220 → **232**。

| 问题 | 定性 | 处理 |
|---|---|---|
| 点「标签页」后侧边栏不关，屏幕两个实例 | **真 bug**（只做了开没做关） | 新增 `src/ui/sidePanel.ts`：`chrome.sidePanel.close({windowId})`（Chrome 141+，须先判存在再调）→ 兜底 `window.close()`。`windowId` 走 `chrome.windows.getCurrent()`，**不需要任何权限** |
| 侧边栏太窄，想要默认 1/3 窗口宽 | **Chrome 硬限制** | `sidePanel` 无宽度 API，做不到。改为一次性宽度引导条如实说明 + 一键升级标签页；README 写入口径并有断言钉着 |
