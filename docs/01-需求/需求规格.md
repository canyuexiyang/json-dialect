# JSON Dialect —— Python/Java JSON 格式互转 Chrome 插件

> 需求规格说明书 v1.0
> 基于 4 轮需求访谈（共 15 个问题）整理，访谈日期：2026-09-20
> 定位：**个人自用工具**，不上架商店，不考虑多用户/登录/云同步

---

## 一、产品定位

一句话：**一个能在浏览器里就地完成 Python 字面量与 Java/标准 JSON 互转的小工具，容错优先，能救就救。**

核心判断：这不是一个"严格 JSON 校验器"，而是一个"格式翻译器"。用户的核心诉求是**把眼前这段文本变成能被目标语言直接吃掉的形态**，而不是验证它是否规范。因此容错（宽松解析）的优先级高于严格性。

---

## 二、核心转换规则（P0，必须实现）

### 2.1 方向一：Python 字面量 → 标准 JSON（Java 侧）

| # | 规则 | 示例 |
|---|---|---|
| 1 | 单引号 → 双引号 | `'name'` → `"name"` |
| 2 | `True` → `true` | `True` → `true` |
| 3 | `False` → `false` | `False` → `false` |
| 4 | `None` → `null` | `None` → `null` |
| 5 | 元组 → 数组 | `(1, 2)` → `[1, 2]` |
| 6 | 末尾多余逗号清理 | `[1, 2, ]` → `[1, 2]` |
| 7 | 键名无引号补引号 | `{name: 'x'}` → `{"name": "x"}` |
| 8 | Python 注释剥离 | `# comment` → 移除 |
| 9 | 字符串内单引号正确转义 | `'it\'s'` → `"it's"` |

**优先级说明**：规则 1–4 是用户明确点名的核心需求，必须 100% 准确。规则 5–9 属于"宽松容错"层，尽力而为。

### 2.2 方向二：标准 JSON → Python 字面量

| # | 规则 | 示例 |
|---|---|---|
| 1 | `true` → `True` | `true` → `True` |
| 2 | `false` → `False` | `false` → `False` |
| 3 | `null` → `None` | `null` → `None` |
| 4 | 双引号 → 单引号 | `"name"` → `'name'` |

**注意**：规则 4 需谨慎处理字符串内部包含单引号的情况（如 `"it's"` → 应保持双引号或正确转义，不能简单替换）。

### 2.3 Java 侧的三种输入形态（都需支持）

用户明确表示"可能都遇到"，需自动识别：

1. **标准 JSON**：`{"name": "张三", "age": 18}`
2. **Java 字符串转义过的 JSON**：`{\"name\": \"张三\"}` —— 需先反转义再解析
3. **Java `Map.toString()` 输出**：`{name=张三, age=18}` —— 非标准格式，需专门解析器

### 2.4 `Map.toString()` 的类型推断规则

输入 `{name=张三, age=18, active=true}` 时：

- `18` → 数字 `18`（不加引号）
- `true`/`false` → 布尔（不加引号）
- 其余 → 字符串（加引号）
- **空值**：`null` → `null`

**用户要求**：智能推断，且**界面上每个值旁提供下拉框可手动改类型**（字符串/数字/布尔/null）。

## 三、界面设计（P0）

### 3.1 整体布局

Chrome 弹窗形式（受 800×600 上限约束），**上下分栏**：

```
┌─────────────────────────────────────┐
│ 识别为：Python 字面量 ▾   [放大] [⚙] │  ← 判定结果可点击切换
├─────────────────────────────────────┤
│                                     │
│   输入区（带语法高亮编辑器）          │
│                                     │
│  行 12 · 字符 348                    │  ← 底部统计
├─────────────────────────────────────┤
│                                     │
│   输出区（带语法高亮，只读/可编辑）   │
│                                     │
│  行 12 · 字符 356                    │
├─────────────────────────────────────┤
│ [转换] [格式化] [压缩] [复制] [下载]  │
└─────────────────────────────────────┘
```

### 3.2 关键交互点

| 元素 | 行为 |
|---|---|
| **顶部判定条** | 显示「识别为 Python 字面量 ▾」，点击可手动切换来源格式，切换后**立即重新转换** |
| **输入区** | 带语法高亮的编辑器（非朴素 textarea）；**粘贴后立即自动识别并转换**，无需点按钮 |
| **输出区** | 语法高亮；`Map.toString` 模式下每个值旁显示类型下拉框 |
| **放大按钮** | 一键在独立窗口打开，突破弹窗 800×600 限制 |
| **统计条** | 输入/输出区各显示行数与字符数 |
| **修正提示条** | 若触发了自动修复，在输入区底部显示「已自动修正 N 处 ▾」，展开列出每处详情（第几行、修正内容） |

### 3.3 按钮功能

- **转换**：手动触发转换（粘贴已自动转了，此为兜底）
- **格式化**：2 空格缩进美化
- **压缩**：压成一行（去空格换行）
- **复制**：一键复制到剪贴板（主要路径）
- **下载**：导出 `.json` 文件（用户只要这一种格式）

## 四、容错与报错（P1，重要）

### 4.1 分层策略

```
第 1 层：标准解析
   ↓ 失败
第 2 层：宽松修复（规则 5–9 + 补括号/补引号）
   ↓ 失败
第 3 层：报错定位
```

### 4.2 用户明确要求的行为

- **尽力修复**：能修的都修，不轻易报错
- **列出所有修正点**：界面顶部展示「已自动修正 N 处」，可展开查看明细（如「第 3 行：键名 name 补充引号」）
- **实在修不好才报错**：高亮出错行 + 标出列号 + 说明原因（如「第 7 行第 12 列：缺少右括号」）

### 4.3 注意

用户未选择「严格模式开关」，因此**不实现**严格校验模式。但报错信息仍需精确到行列，这是用户明确要的。

## 七、技术选型建议

基于需求特点（个人自用、无需后端、纯前端转换、需语法高亮），建议：

| 维度 | 建议 | 理由 |
|---|---|---|
| 插件规范 | **Manifest V3** | Chrome 已停止支持 MV2 新装 |
| 框架 | **原生 HTML/CSS/JS 或 React + Vite** | 功能简单，原生即可；若想高亮编辑器体验好，React 更省心 |
| 语法高亮 | **CodeMirror 6** 或 **Prism + textarea 叠加** | CodeMirror 6 成熟且支持只读/编辑切换；Prism 方案更轻 |
| 解析器 | **自研宽松解析器**（不用 JSON.parse） | 标准 JSON.parse 无法满足容错需求（单引号、末尾逗号、Map.toString 全都不认） |
| 构建 | Vite | 打包干净，产物小 |

**关键提醒**：核心难点不在界面，而在**自研宽松解析器**。建议把解析器逻辑做成纯函数、单独文件、可脱离浏览器单元测试——这样转换规则（尤其是第 2.1 节的 9 条规则和 Map.toString 的类型推断）能独立验证正确性，避免在插件里反复手测。

## 八、待确认问题

以下问题在访谈中未覆盖，建议开发前确认：

1. **字符串内含单引号的反向转换**：`"it's"` 转 Python 时，期望输出 `'it\'s'` 还是 `"it's"`（保持双引号）？
2. **数字精度**：超大整数（如 `12345678901234567890`）是否需要保持精度，还是可以转科学计数法？
3. **嵌套 Map.toString**：`{user={name=张三, age=18}}` 这种嵌套结构是否需要支持？
4. **混合输入**：一段文本里既有 Python 又有 JSON 片段时，按整体判定还是分段处理？

## 九、验收标准（草案）

| # | 场景 | 期望结果 |
|---|---|---|
| 1 | 输入 `{'name': '张三', 'age': 18, 'vip': True}` | 输出标准 JSON，`"vip": true`，中文不转义，2 空格缩进 |
| 2 | 输入 `{"a": null, "b": false}` 反向转换 | 输出 `{'a': None, 'b': False}` |
| 3 | 输入 `{name=张三, age=18}` | 智能推断为 `{"name": "张三", "age": 18}`，且值旁有类型下拉 |
| 4 | 输入 `{\"name\": \"x\"}` | 自动识别为转义字符串，反转义后正确解析 |
| 5 | 输入 `{'a': 1, }` （末尾逗号） | 自动修复并提示「已自动修正 1 处」，不报错 |
| 6 | 输入 `{'a': 1` （缺右括号） | 高亮第 1 行，提示「缺少右括号」并标列号 |
| 7 | 输入 500 行嵌套 JSON | 转换耗时 < 500ms，界面不卡顿 |
